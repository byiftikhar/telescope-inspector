Telescope Inspector

A fast, searchable viewer for Laravel Telescope, the debug assistant for the Laravel framework. Search, filter and prune entries without the page freezing on big requests.

View on GitHub Packagist 
composer require byiftikhar/telescope-inspector --dev

Why Telescope Inspector?

Never freezes

Telescope loads 50 full entries at once, so one heavy request can stop its page loading. The inspector fetches small batches and keeps only a summary.

Search everything

Find requests, jobs, queries, logs and exceptions by route, controller, SQL or message, and filter by method, status, user and duration.

Every query of a request

Open any request to see its queries with total time, slow queries and repeated statements (possible N+1), plus logs, jobs and exceptions.

Prune by date

Delete entries in a date range, per type, keeping exceptions if you like, with a live count and a confirmation first.

Light and dark

A clean developer-tool design that follows your system theme, with clean, shareable URLs for every entry.

Drop-in and safe

No tables or migrations. Uses Telescope's own API and access gate, and never records its own traffic.

Frequently asked questions

Why does the Laravel Telescope requests page not load?

Telescope's list endpoint returns the full content of 50 entries at a time. A few large payloads or responses make that several MB. Telescope Inspector fetches 10 to 50 entries at a time and never renders the large parts in the list.

How do I search Laravel Telescope entries by URL or route?

Type any part of the URI or controller in the search box. All words must match, so orders store finds POST /api/orders.

How do I find slow or N+1 queries in Telescope?

Open a request: its Queries tab shows total query time, slow queries and repeated statements for that request.

How do I prune Laravel Telescope entries by date?

Click Prune, choose a quick range or a From/To date, optionally pick entry types, check the count and confirm.

Does it replace Laravel Telescope?

No. Telescope keeps recording exactly as before; this is a faster, searchable screen on top of its data.
